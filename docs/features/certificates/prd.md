# Product Requirements Document (PRD)
## Feature: ระบบบริการออกหนังสือรับรอง (Certificate Request System)

### 1. วัตถุประสงค์ของระบบ (Objective)
เพื่อพัฒนาระบบให้บริการขอออกเอกสารและหนังสือรับรองต่างๆ สำหรับนิสิตและบุคลากรของคณะพุทธศาสตร์ ผ่านระบบออนไลน์ โดยครอบคลุมตั้งแต่การยื่นคำร้องผ่าน Public Portal การตรวจสอบและอนุมัติโดยเจ้าหน้าที่ผ่าน Admin Console ไปจนถึงการออกเอกสาร (สามารถดาวน์โหลดเป็น PDF หรือแจ้งเตือนให้มารับเอกสารตัวจริง)

### 2. กลุ่มผู้ใช้งาน (User Personas & Roles)
1. **นิสิต (Student)** - ผู้ใช้งานผ่าน Portal สามารถยื่นคำร้อง ติดตามสถานะคำร้อง และดาวน์โหลดเอกสารอิเล็กทรอนิกส์
2. **อาจารย์/บุคลากร (Staff/Faculty)** - ผู้ใช้งานผ่าน Portal สามารถยื่นคำร้องขอหนังสือรับรองที่เกี่ยวข้องกับการทำงาน
3. **เจ้าหน้าที่ทะเบียน/ฝ่ายเอกสาร (Admin/Registrar)** - ผู้ใช้งานผ่าน Admin Console มีหน้าที่ตรวจสอบความถูกต้องของข้อมูล อนุมัติ/ปฏิเสธคำร้อง และออกเอกสาร

### 3. Functional Requirements & Use Cases

#### 3.1 ฝั่ง Portal (สำหรับผู้ยื่นคำร้อง)
- **FR-P1: การยื่นคำร้อง (Submit Request)** 
  - ผู้ใช้สามารถเลือกประเภทหนังสือรับรองที่ต้องการ
  - กรอกข้อมูลที่จำเป็นตามประเภทเอกสาร และแนบไฟล์เอกสารประกอบ (ถ้ามี)
- **FR-P2: การติดตามสถานะ (Track Status)**
  - ผู้ใช้สามารถดูรายการคำร้องที่ตนเองเคยยื่น และดูสถานะปัจจุบัน
- **FR-P3: การรับเอกสาร (Receive Document)**
  - ผู้ใช้สามารถกดดาวน์โหลดไฟล์ PDF ได้จากระบบ หรือดูข้อความนัดหมายมารับตัวจริง

#### 3.2 ฝั่ง Admin (สำหรับเจ้าหน้าที่)
- **FR-A1: การจัดการรายการคำร้อง (Manage Requests)**
  - ดูรายการคำร้องทั้งหมด พร้อมตัวกรอง (Filter)
- **FR-A2: การตรวจสอบและพิจารณา (Review & Approve)**
  - อนุมัติคำร้อง (Approve) หรือ ปฏิเสธคำร้องพร้อมระบุเหตุผล (Reject)
- **FR-A3: จัดการประเภทหนังสือรับรอง (Manage Certificate Types)**
  - เพิ่ม/แก้ไข/ลบ ประเภทของหนังสือรับรอง (Master Data)

### 4. Acceptance Criteria (เกณฑ์การตรวจรับงาน)
- [ ] นิสิต/อาจารย์ สามารถสร้างคำร้องขอเอกสารได้สำเร็จ (สถานะ PENDING)
- [ ] เจ้าหน้าที่สามารถเปลี่ยนสถานะคำร้องจาก PENDING -> APPROVED หรือ REJECTED ได้
- [ ] หากเจ้าหน้าที่กด REJECTED ต้องบังคับให้กรอกเหตุผล
- [ ] การแสดงผลรองรับสองภาษา (TH/EN) และการเรียก API มีการทำ RBAC อย่างเข้มงวด
