# Product Requirements Document (PRD): ระบบจัดการข่าวสารประชาสัมพันธ์ (News)

## 1. Objective (วัตถุประสงค์ของระบบ)
- เพื่อเป็นช่องทางหลักในการเผยแพร่ข่าวสาร ประกาศ และกิจกรรมต่าง ๆ ของคณะพุทธศาสตร์ให้แก่นิสิต บุคลากร และบุคคลทั่วไป
- เพื่อให้เจ้าหน้าที่สามารถจัดการข่าวสารได้อย่างมีประสิทธิภาพ มีระบบตรวจสอบและอนุมัติ (Review/Approve) ก่อนเผยแพร่สู่สาธารณะ

## 2. User Personas & Roles
- **Guest / Student (บุคคลทั่วไป/นิสิต):** ผู้ใช้งานที่ไม่ได้ล็อกอิน สามารถเข้ามาอ่านข่าวสาร ค้นหา กรองหมวดหมู่ และดาวน์โหลดไฟล์แนบได้ผ่านหน้า Portal
- **Author (ผู้ร่างข่าว - `news:write`):** เจ้าหน้าที่ที่มีสิทธิ์สร้าง แก้ไข และแนบไฟล์ข่าวสาร แต่อาจไม่มีสิทธิ์เผยแพร่เอง ต้องส่งให้ผู้อนุมัติตรวจสอบ
- **Reviewer (ผู้อนุมัติ/บรรณาธิการ - `news:approve`):** เจ้าหน้าที่ระดับหัวหน้าหรือผู้มีอำนาจ สามารถตรวจทาน แก้ไข และกดอนุมัติเผยแพร่ หรือตีกลับข่าวสารได้
- **Admin (ผู้ดูแลระบบ - `news:manage`):** สามารถจัดการข่าวสารทั้งหมด รวมถึงการลบ หรือปักหมุดข่าวสารสำคัญ

## 3. Functional Requirements & Use Cases
**ฝั่ง Portal (หน้าบ้าน):**
- **UC-P1:** ผู้ใช้สามารถดูรายการข่าวสารล่าสุด แยกตามหมวดหมู่ได้ (ACADEMIC, EVENT, GENERAL, PROCUREMENT, BUDDHIST_AFFAIRS)
- **UC-P2:** ผู้ใช้สามารถค้นหาข่าวสารด้วยคำค้น (Search)
- **UC-P3:** ผู้ใช้สามารถคลิกอ่านรายละเอียดข่าวสาร ดูรูปภาพหน้าปก และดาวน์โหลดไฟล์แนบได้
- **UC-P4:** ระบบมีการนับจำนวนยอดเข้าชม (View Count) ของข่าวสาร

**ฝั่ง Admin Console (หลังบ้าน):**
- **UC-A1:** เจ้าหน้าที่สามารถดูรายการข่าวสาร (Data Table) พร้อมตัวกรองตามสถานะ (DRAFT, PENDING_REVIEW, PUBLISHED, ARCHIVED) และหมวดหมู่
- **UC-A2:** เจ้าหน้าที่สามารถสร้างข่าวสารใหม่ (ใส่รูปปก, ชื่อเรื่อง TH/EN, สรุป, เนื้อหา, หมวดหมู่) และบันทึกเป็น DRAFT ได้
- **UC-A3:** เจ้าหน้าที่สามารถแนบไฟล์ประกอบข่าวสารได้หลายไฟล์ (PDF, Image)
- **UC-A4:** เจ้าหน้าที่สามารถกดส่งเรื่องเพื่อขออนุมัติ (Submit for Review)
- **UC-A5:** ผู้อนุมัติสามารถกดเผยแพร่ (Publish) หรือตีกลับพร้อมเหตุผล (Reject) ได้
- **UC-A6:** ผู้ดูแลระบบสามารถตั้งค่าให้ข่าวสารนั้นเป็น "ข่าวปักหมุด" (Pinned) ได้

## 4. Acceptance Criteria
- หน้า Portal แสดงเฉพาะข่าวสารที่มีสถานะ `PUBLISHED` เท่านั้น
- ผู้เขียนข่าวไม่สามารถอนุมัติข่าวที่ตนเองเขียนได้ (เว้นแต่จะมีสิทธิ์ Approve)
- การสร้างข่าวต้องระบุชื่อเรื่องและเนื้อหา (ภาษาไทยเป็นบังคับ) 
- รองรับการลบไฟล์แนบที่ไม่ได้ใช้แล้ว
- ทุกการแก้ไข (Create/Update/Delete) ต้องถูกบันทึกใน Audit Log (ตามมาตรฐาน VibeCore)
