# Product Requirements Document (PRD)
## Feature: ระบบจองห้องประชุมประจำคณะพุทธศาสตร์ (Meeting Rooms)

### 1. วัตถุประสงค์ของระบบ (Objective)
เพื่ออำนวยความสะดวกให้คณาจารย์และเจ้าหน้าที่สามารถตรวจสอบตารางการใช้งาน และทำการจองห้องประชุม/ห้องบรรยายของคณะพุทธศาสตร์ได้อย่างเป็นระบบ ป้องกันการจองซ้อนทับกัน

### 2. กลุ่มผู้ใช้งาน (User Personas & Roles)
1. **คณาจารย์ / เจ้าหน้าที่ (Staff)** - เข้าสู่ระบบเพื่อดูตารางห้องว่าง และส่งคำขอจองห้องประชุม
2. **เจ้าหน้าที่ดูแลอาคาร (Admin)** - อนุมัติ/ปฏิเสธคำขอจอง และจัดการข้อมูลห้องประชุม (เพิ่ม/ลดห้อง)

### 3. Functional Requirements & Use Cases

#### 3.1 ฝั่ง Portal (สำหรับผู้ใช้ทั่วไป / Staff)
- **FR-P1: ตรวจสอบตาราง (Room Schedule)**
  - ดูปฏิทินหรือรายการห้องประชุมและสถานะการจองในแต่ละวัน
- **FR-P2: จองห้องประชุม (Book Room)**
  - ผู้ใช้ที่ล็อกอินสามารถเลือกห้อง วัน เวลาเริ่มต้น และเวลาสิ้นสุด เพื่อส่งคำขอจอง
  - ระบบตรวจสอบว่าไม่มีการจองซ้อนทับ (No overlap)

#### 3.2 ฝั่ง Admin (หลังบ้าน)
- **FR-A1: จัดการห้องประชุม (Manage Rooms)**
  - เพิ่ม แก้ไข ลบ ข้อมูลห้องประชุม (ชื่อห้อง, ความจุ, อุปกรณ์, รูปภาพ, สถานะการใช้งาน)
- **FR-A2: อนุมัติการจอง (Approve Bookings)**
  - ดูรายการคำขอจองห้องทั้งหมด
  - อนุมัติ (APPROVED) หรือ ปฏิเสธ (REJECTED) คำขอจอง

### 4. Acceptance Criteria
- [ ] มีตารางห้องประชุม (MeetingRoom) และคำขอจอง (MeetingBooking)
- [ ] ระบบมี Logic ตรวจสอบการจองซ้อนเวลา (Overlapping bookings) ก่อนบันทึกลงฐานข้อมูล
- [ ] ฝั่ง Admin สามารถดูรายการคำขอและกดอนุมัติ/ตีกลับได้
- [ ] ฝั่ง Portal แสดงรายการห้องประชุม และฟอร์มสำหรับส่งคำขอจอง
